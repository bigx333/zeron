# Create a project from GitHub

Open **New project** and choose the computer that should hold the checkout. On desktop, select **Clone from GitHub** alongside Home and the device's drives. On iOS and Android, switch from **Folder** to **GitHub**.

Zeron lists repositories available to that device's active GitHub CLI account, including private repositories and repositories shared through collaborators or organizations. Recent repositories appear first; more pages load in the background. Search by repository or owner name. On mobile, select a repository and tap **Clone** to add it to the new-session project picker. On desktop, selecting a repository or pressing Enter clones it and opens the project; the footer's **Clone project** button and Cmd/Ctrl+Enter do the same.

The selected device needs Git, [GitHub CLI](https://cli.github.com/), and an account connected with [`gh auth login`](https://cli.github.com/manual/gh_auth_login). Missing CLI or authentication errors include setup guidance and a Retry button. Remote devices use their own account and credentials. Forks clone only the selected repository; cloning does not add or fetch its upstream automatically. Neither the Android device nor the iPhone needs GitHub CLI, a GitHub token, or a local Git installation.

Clones are stored at `<engine data directory>/repos/github.com/<owner>/<repository>`, with the owner and repository lowercased to keep checkout paths stable across GitHub casing changes. Different owners can have repositories with the same name. A retry reuses a checkout only when its GitHub origin matches and Zeron recorded a successful clone. Incomplete checkouts are preserved and reported with recovery guidance; unrelated folders are preserved and reported as conflicts. An existing project for that checkout is selected without creating a duplicate, including when another client creates it concurrently. New GitHub projects use a shared deterministic identity for the execution device and checkout path, so independent coordinators converge on one registry row.

On desktop, cloning continues if the picker is dismissed. Completion adds the project without navigating away from a newly opened picker. Mobile keeps the picker open while cloning and prevents changing hosts until it finishes. Cloning and repository listing never require entering a token in Zeron.

The device RPCs are `ListGitHubRepos { cursor? }` and `CloneGitHubRepo { repository }`, both supporting `targetDeviceId`. Listing returns `login`, `repositories` (`nameWithOwner`, `description`, `isPrivate`), and `nextCursor`. Cloning returns the normal `Repo` response; project creation uses the existing `createSpace` workspace mutation, which now also returns the authoritative `space` row. Desktop supports older coordinators through `WatchSpaces`; mobile waits for the host's registry row to synchronize before returning a project ready for session creation. Clones of different repositories can run concurrently; waiting and cloning share a 14-minute budget within the 15-minute relay deadline. Timeout or cancellation terminates the owned CLI process group on Unix and the process job on Windows, including its Git transport children.
