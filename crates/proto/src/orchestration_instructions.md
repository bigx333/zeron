Zeron provides app-owned orchestration through its MCP server. Follow the user's delegation preferences and repository instructions; tool availability alone does not authorize delegating work.

- For managed child work, use `delegate_task`. Discover live provider/model IDs and feature support with `orchestrator_capabilities`; a provider's native model list is not the full Zeron catalog. Native subagents may suit same-provider work when they support the requested model. Use managed delegation for cross-provider work, durable task results, or a separate checkout. Give each child a self-contained brief: parent history is not copied. Settings and permissions inherit, and children cannot gain broader permissions.
- Keep the returned `taskId` and `childChatId`. Manage a task with `task_status` and `task_cancel`. The child chat stores the conversation; sending another message to it does not reopen a completed managed task. For each delegated review round, call `delegate_task` again with the original brief, prior findings, responses and unresolved objections. Use a distinct `client_request_id` for each round, stable across retries of that round.
- Launch independent work with `mode: "async"` before waiting for results. Continue useful independent work, then end your turn when only delegated work remains: durable completion automatically wakes or steers the parent. Do not busy-poll. Use `mode: "wait"` when you need an immediate result; a timeout never cancels the task. If `hasPendingQuestion` is true, inspect the child with `get_chat` or `list_pending_inputs` and answer with `respond_to_input`, or obtain the missing decision from the user.
- `isolation: "shared"` uses the parent's checkout. Coordinate writes to avoid collisions. `isolation: "worktree"` creates a separate checkout from the parent's local HEAD and runs project setup; uncommitted edits are not copied. Include needed uncommitted context explicitly in the brief. `merge_chat` transfers a result as conversation context; it does not merge Git changes.
- `create_chat(s)` creates ordinary conversations, and `send_message(s)` continues them. Use these for requested conversations rather than as a substitute for managed tasks. `fork_chat` branches a conversation at a completed response. The engine chooses an independent native fork where supported and portable visible history otherwise. Provider switching and reactivation are handled by the engine; do not share or edit native session IDs yourself.
- `chat_checkpoints` lists durable history and authoritative restore availability. Completed turns create checkpoints automatically. `create_chat_checkpoint` saves an idle chat before an experiment. `rollback_chat` restores conversation and available checkout files only when the chat, delegated work and shared checkout are idle; honor `blockedReason`. Preserve its returned `recoveryCheckpointId` for Undo. Use a stable `client_request_id` for restore retries; restore the recovery point to undo. Restores preserve Git HEAD/index, ignored files and current permissions.

Tool names may have an MCP prefix such as `mcp__zeron__delegate_task`. If tools are attached lazily, discover them before declaring orchestration unavailable. Report unsupported operations accurately and keep waits bounded.
